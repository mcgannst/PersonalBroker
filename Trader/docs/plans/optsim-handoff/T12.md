## For T16
- `OptionsWorker(deps: OptionsWorkerDeps)`; `async step() -> StepReport`; `async run(stop: asyncio.Event, *, once=False)`.
- `OptionsWorkerDeps` fields: `factory` (`sessionmaker[Session]`); `engine` (`sqlalchemy.Engine`, holds the lock on one dedicated connection); `clock`; `calendar`; `settings` (`Callable[[], OptionSettings]`, e.g. `store.load`); `run_id` (`int | None`: pass `active_options_run_id(factory)` at build time, the same run the broker was built for); `broker` (`OptionBroker`); `record_marks` (`OptionMarketService.record_marks`); `host` (`StrategyHost`); `prompt_sender` (anything with `async send_due(now) -> int`); `notifier` (**must send directly: the worker has no relay loop**); `renderer` (`OptionMessages`); `sleep` (defaults to `asyncio.sleep`).
- **Entry point:** `python -m trader.options.worker [--once]`. `main()` calls `bootstrap.build_core()`, opens an `AsyncExitStack`, then `await trader.options.runtime.build_worker_deps(core, stack)` and runs the worker. **T16 provides `trader.options.runtime.build_worker_deps`.**
- **No options run at build time:** `build_worker_deps` must still return deps with `run_id=None`; the worker then idles (lock, `ensure_defaults`, heartbeat) and never calls the broker, so a placeholder broker is fine. When a run appears the worker exits with code 4 and supervisord restarts it on the new run.
- Lock: session advisory lock, key = blake2b-8 of `"trader.options_worker"` (`LOCK_NAME`), separate from the stock worker's.
- Heartbeat: process `options-worker`; phases `starting`, `session`, `idle`, `stopped`; detail `{run_id, fills_today, last_event}`.
- Exit codes: 0 normal stop; 1 setup failed; 2 another options worker holds the lock (it sleeps 30 s first, so no wrapper script); 3 lock lost; 4 the active options run differs from `deps.run_id`. Supervisord restarts on all of them.
- Shutdown: SIGTERM/SIGINT set `stop`; the part in progress finishes, then the `stopped` heartbeat and lock release. 30 s `stopwaitsecs` is enough unless one strategy event or Questrade call runs longer.
- `run_event_cli(host, *, strategy, key, session_date, force, due, now) -> int`: one line per event; returns 0, 1 if any event failed, 2 for an unknown strategy, a bad event key or missing arguments. `now` is required (extra to the plan); `session_date` must be a real `date` (T16 defaults it to today ET).

## Behaviour
- Cadence: in the session one step per `options.quote_poll_seconds`; outside it every 30 s. All timers are "due now" after a restart.
- A failing strategy event is re-offered after 60 s, doubling to a 15-minute cap (in memory: a restart gives one extra try).
- Events fire only inside session hours; one missed while the worker was down past the close is left to the `options-event --due` cron line.
- Day orders: `expire_day_orders` runs on the first step at or after the close of a session day.
- Strike-touch reads the underlying price from the marks table (written by `record_marks`); a mark older than one `options.mark_seconds` is ignored. Rows are `event_log` level `warning`, source `options.worker`, with `underlying`, `structure_id`, `kind: STRIKE_TOUCHED`; message dedupe key `strike_touched:<structure id>:<session date>`.
- Snapshots are written even when `marks_complete` is False (positions carried at cost).
- **Known limit:** if the process dies between `broker.poll` returning a fill and the fill message / `host.deliver_fill`, that message and `on_fill` are lost (the fill itself is safe in the database; there is no delivered marker for fills). A restart between steps loses and duplicates nothing.
