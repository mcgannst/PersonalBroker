- Route `/options` sits behind `RequireAuth` inside the Layout. Deep links: `?tab=account|positions|trade|orders|strategies|activity|settings` and `?prompt=<id>` (so Telegram's prompt links work); both survive the login redirect.
- `OptionsApiProvider` is mounted in `App` (not `AppRoutes`); tests use `pages/options/testRender.tsx` (`renderOptions`).
- CSRF: the options client reads the token from the main HTTP client and refreshes it through `me()` on a 403 `csrf`.
- **Error codes the page relies on**: 409 with code `no_options_run` shows "No options run yet"; 409 on a prompt answer shows "already answered"; 422 `fields[].msg` is shown under the field. T16 checks T14 returns these.
- Cancel and Reprice appear only when `order.source === "manual"`.
- Polling: account, positions, working orders, chain quotes every 5 s; the rest every 30 s.

## Panel behaviour (for T11's panel)
- `PanelAction` does not say whether an action is per row or panel-wide: the page offers an action on the rows that list it, and offers panel-wide (no `row_id`) only the actions no row lists. A row action whose table is currently empty shows as a panel-wide control.
- A row toggle starts from the row's cell with the same key when it is a boolean; a panel-wide toggle starts unchecked.
- `manual_events` are not shown (no route fires one).
- On a phone, Options is the first item under More (the tab bar is pinned at four); in the side nav it is right after Dashboard.
