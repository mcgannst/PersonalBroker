## Import and constructor
- `from trader.options.lifecycle import LifecycleEngine, MissingClose, EVENT_SOURCE, moneyness`
- `LifecycleEngine(factory, clock, calendar, market, settings, run_id, book_factory, official_close)`
  - `settings` is an `OptionSettings` VALUE (not the store): build the engine per job run.
  - `book_factory: Callable[[Session], OptionBook]`, e.g. `lambda s: DbBook(s, run_id, Ledger(calendar), clock)`.
  - `official_close: Callable[[str, date], Awaitable[Decimal | None]]`, called as `(ticker, day)`.
- Methods, all returning `list[LifecycleEvent]`: `await run_expiry(session_date)`, `await run_early_assignment(session_date)`, `await check_adjustments()`.

## What T13 must do
- **Past-date closes.** `run_expiry` asks for the close of each contract's EXPIRY date (or the session before it), not of `session_date`. On a catch-up run that is an earlier day, so `official_close` must use the daily candle for any day other than today, never the live quote.
- **Missing closes.** `engine.missing_closes` is a list of `MissingClose(underlying, close_date, structure_ids)`. `run_expiry` resets it; `run_early_assignment` appends. Read it after both calls: non-empty means the job ends `failed` (and retries).
- **Freeze alert.** A frozen (adjusted) contract is a `warning` row in `event_log`; the engine has no notifier, so T13 sends the Telegram message for each returned `frozen` event.
- The engine opens its own `session_scope` per structure and calls `lock_book` itself: do not call it inside another transaction that already holds the book.
- Early assignment reads `market.facts(ticker)` for `next_ex_dividend_date` (must equal `calendar.next_session(session_date)`) and `dividend_per_share`, `official_close(ticker, session_date)`, and `market.quotes([contract_id])` for the midpoint. No quote counts as zero time value (the call is assigned).
- `check_adjustments` uses `market.contract`, `market.expiries`, `market.strikes`; an underlying whose `expiries()` is empty freezes nothing.

## Behaviour
- Event fields: `session_date` is the run's date; `underlying_close` the close used; `qty` contracts, unsigned; `cash_delta` includes the fee; `new_structure_id` only for shares put into a new structure (assigned put, exercised long call). The stored row's `detail` holds `settled` (`expired`, `shares` or `intrinsic`), `close_date`, `right`, `position_qty`, `fee`.
- Ledger refs `opt_life:<event id>`, kinds `buy`, `sell`, `fee`.
- A short call not delivered from held shares (the short leg of a vertical, or cash-settled) is recorded as `assigned`, not `called_away`. Early assignment: event kind `early_assignment`; both structures close as `called_away`.
- A cash-settled leg is still charged `options.assignment_fee`.
- **Covered calls:** shares are taken from the call structure's own shares position first (a buy-write), then from `cover_structure_id`. **If `cover_structure_id` is not set (T4/T5), a covered call is cash-settled at intrinsic as if uncovered: T16 checks this end to end.**
- **Shares structure convention (check against T5 in T16):** the new shares structure has `qty` = contracts and `entry_net` = -strike x multiplier / 100.
- In a vertical with both legs in the money the ledger briefly shows the buy before the sell; feasibility is judged on the night's net against free cash.
- "No official close" is an `error` row in `event_log` (source `options.lifecycle`) plus `missing_closes`.
